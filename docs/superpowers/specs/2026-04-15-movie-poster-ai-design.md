# 研究計畫草稿

**中文題目：** 電影海報自動生成與品質評估：基於大型語言模型的自適應框架
**英文題目：** Automatic Movie Poster Generation and Quality Evaluation: An Adaptive LLM-Driven Framework

---

## 1. 研究背景與動機

電影海報是電影行銷的核心視覺素材，一張好的海報需要同時傳達電影類型、情感氛圍與商業吸引力。傳統上，海報設計高度依賴人工，成本高且週期長。

近年來，生成式 AI（Stable Diffusion、DALL-E 等）讓自動圖像生成成為可能，但目前研究存在兩個主要缺口：

1. **缺乏領域專屬評估指標**：現有指標並非針對電影海報設計，無法有效衡量「類型一致性」或「商業吸引力」
   - **FID**（Fréchet Inception Distance）：只衡量生成圖像與真實圖像的整體統計分佈差異，無法判斷「這張海報看起來像動作片嗎？」
   - **CLIP Score**：衡量圖像與文字的通用語意相似度，沒有針對電影海報領域設計，無法評估視覺吸引力或與劇情的契合度
2. **生成與評估脫節**：大多數系統只做生成，沒有利用評估結果來自動改善輸出品質

本研究旨在填補這兩個缺口。

---

## 2. 研究目標

1. 提出一套**電影海報專屬的多維品質評估框架**，並驗證其與人類評分的相關性
2. 設計一個以 LLM 為核心的**自適應生成系統**，透過評估分數自動回饋優化提示詞，迭代提升海報品質

---

## 3. 核心貢獻

| 貢獻 | 說明 |
|---|---|
| **貢獻一：評估框架** | 提出涵蓋三個維度的海報品質評估指標，並建立與人類評分的對齊驗證 |
| **貢獻二：自適應生成** | 設計 LLM 驅動的提示詞自動迭代優化機制，無需人工介入即可提升品質 |

---

## 4. 評估框架（貢獻一）

提出三個維度的自動評估指標：

### 4.1 類型一致性（Genre Consistency Score）
- 使用 CLIP 計算生成海報與電影類型描述文字之間的語意相似度
- 例：動作片海報應與「action, fight, explosion, hero」等描述高度對齊

### 4.2 視覺吸引力（Visual Appeal Score）
- 使用 NIMA（Neural Image Assessment）美學評分模型
- 評估NIMA（Neural Image Assessment構圖、色彩、清晰度等視覺品質

### 4.3 語意對齊（Semantic Alignment Score）
- 使用 CLIP 計算生成海報與電影劇情摘要的語意相似度
- 確保海報內容與電影實際內容一致

### 4.4 人類偏好驗證
- 使用 **TMDB 觀眾評分**（1–10 分）作為人類偏好的代理指標（proxy）
- 假設：高評分電影的官方海報更受觀眾喜愛
- 計算自動評估指標與 TMDB 評分的 Pearson 相關係數，驗證指標有效性
- 無需額外問卷收集，資料已在現有資料收集架構中
- *若教授要求更嚴謹驗證，可補充小規模問卷（20 張海報、10–15 位受測者）*

## 5. 自適應生成系統（貢獻二）

### 5.1 系統架構

```
電影 Metadata（類型、劇情摘要、評分）
        ↓
[LLM 提示詞生成模組]  ← 根據評估分數修改提示詞（迭代）
        ↓
[圖像生成模組] Stable Diffusion（本地，16GB GPU）
        ↓
[多維評估模組] CLIP + NIMA
        ↓
   分數是否達標？
    ├─ 是 → 輸出最終海報
    └─ 否 → 回饋給 LLM → 重新生成（最多 3–5 次迭代，可設定）
```

### 5.2 各模組說明

| 模組 | 技術 | 說明 |
|---|---|---|
| 資料模組 | TMDB API | 電影 metadata、官方海報、觀眾評分 |
| LLM 提示詞生成 | Claude / GPT-4 API | 分析電影資訊，生成圖像生成提示詞 |
| 圖像生成 | Stable Diffusion（本地） | 依提示詞生成電影海報 |
| 多維評估 | CLIP、NIMA | 對生成結果打分 |
| 回饋優化 | LLM + 評估分數 | 將分數與問題描述回饋給 LLM，生成改良提示詞 |

### 5.3 實驗設計

比較以下條件下的海報品質：

| 條件 | 說明 |
|---|---|
| Baseline | 直接用電影標題生成，無任何提示詞工程 |
| 無迭代 | LLM 生成提示詞，但只生成一次 |
| 有迭代（本研究） | LLM 提示詞 + 評估回饋自動迭代優化 |

## 6. 資料來源

本研究統一使用 **TMDB API** 作為單一資料來源，簡化資料管線並確保格式一致。

| 資料 | TMDB 欄位 | 用途 |
|---|---|---|
| 電影類型 | `genres` | LLM 提示詞生成、類型一致性評估 |
| 劇情摘要 | `overview` | LLM 提示詞生成、語意對齊評估 |
| 官方海報 | `poster_path` | 評估基準（reference poster） |
| 觀眾評分 | `vote_average` | 人類偏好代理（proxy） |
| 關鍵字、演員 | `keywords`, `credits` | 選用，可豐富提示詞內容 |

> **資料收集進度超前：**
> - ✅ 10,000 部電影 metadata 已收集（`tmdb_top_rated_movie_details_10000.csv`）
> - ✅ 海報批次下載腳本已完成（`download_images_from_csv.py`）
> - ✅ 圖像 CLIP embedding（512 維）已預先計算（`movie_image_text_features.csv`）
> - ✅ `consistency_score` 已初步計算，可直接作為評估框架的起點
>
> **資料使用規劃：**
> - 評估框架驗證：全部 10,000 部電影的官方海報（大規模統計驗證）
> - 生成實驗：從中抽取 150 部電影作為測試集（每種類型各 25 部，涵蓋 6 種主要類型）
>
> 論文聲明：*"Data collected via TMDB API for academic research purposes."*
